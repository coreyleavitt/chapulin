# RFC: Verification Harness v2 — facade, symex depth, soak corpus

**Status:** reviewed (Stage 2 — both architect rounds complete; ready for `/tdd`, sequence-gated on the BlockSource/BlockSink RFC for A1b+)
**Predecessor:** `verification-harness.md` (v1, complete — fuzz + symex + hostile-session data phase, Stage 4 reviewed).
**Handoff:** `verification-harness-v2.handoff.md`

## 1. Motivation

v1 verified the never-throw-Defect security property over chapulin's **parse / containment / queue** layers (coverage-guided fuzz + bounded z3 symex) and the **post-negotiation data phase** (the `t_hostile.nim` stateful harness over `Wire`). Stage-4 review confirmed those are *genuine* (not vacuous) but recorded three honest gaps, which v2 closes:

- **The `api.nim` facade — the never-throw boundary itself — is verified only *transitively*.** Nothing drives hostile bytes through the session's own entry points (`startTransfer`/`poll`/`drain`/`cancel`/`close`). We've proven the layers *below* it don't raise Defects; we have **not** proven api.nim's own orchestration never leaks a `Defect` *past* its `except CatchableError` boundaries (`api.nim:411,586,635,668`) — and a `catch CatchableError` does not catch a Nim `Defect`. This is the highest-value gap: it's the surface an embedder actually touches (RFC #17) and where the whole `SECURITY.md` never-throw claim is *enforced*, not merely relied upon.
- **`maxConcurrent` enforcement is untested** — only config-plumbing is verified, not that the (N+1)th concurrent transfer is actually rejected/queued.
- **Symex reaches only the option parsers**, and **fuzzing is fixed-seed × `FuzzN=200`** with no mechanism to grow a real corpus — the committed corpus is a thin coverage-guided seed, not a campaign product.

## 2. Goals / non-goals

**Goals.**
- **A.** Verify the never-throw boundary at `api.nim` *directly*: a stateful property driving a real `TftpSession` over `Wire`, under arbitrary op interleavings + hostile packet injection, asserting no Defect ever escapes the facade — and fold in `maxConcurrent` enforcement.
- **B.** Extend bounded symex no-Defect proofs *downward* to more pure cores: `protocol.decode`, the lexical half of `security.validatePath`/`checkWriteAccess`, `checksum.writeSidecar`; retire the `parseInt`→`parseBiggestInt` substitution in the tsize twins.
- **C.** Stand up a coverage-guided **soak campaign** (proptest's currently-unused `fuzzWith` engine) that grows and minimizes the committed corpus, seeded from boundary values + real interop-captured packets, with coverage-gap reporting.

**Non-goals.**
- Reintroducing libFuzzer/AFL — proptest is the chosen engine (the FFI-free-in-tests bar wouldn't block it, but it cuts against the June-2026 decision; out of scope).
- Proving anything about *real* socket/file I/O — symex can't model it; the harness mocks it via `Wire`. The guarantee is over decision logic + orchestration, not the OS.
- Changing the **fast deterministic default suite** (fixed seed × `FuzzN`) — *behaviorally*. Note (architect r1): the soak *does* grow the committed corpus the default replays, so it changes the default's wall-clock (replay scales with corpus size) — capped by C4's per-target size ceiling (§3.3). Data, not code.
- Closing the Windows-reserved-device-name containment residual (a `src/` feature with its own design questions — separate hardening RFC).

> **Correction (architect r1; sharpened r2):** the earlier "**zero production refactor**" framing is **false for A4**, and the change is larger than "one line." The `maxConcurrent`/`checkHostAccess` rejection branches call `newUdpTransport(0)` **directly at three sites** (`server.nim:701` no-ports, `852` host-access reject, `862` maxConcurrent reject), bypassing `server.transferFactory` — so a Wire-backed session's rejection opens a *real OS socket* and is *unobservable* on the mock. A4 requires: **(i)** rerouting all **three** sites through `transferFactory` (mechanical, but each keeps its own `try/except OSError, CatchableError` wrapper — model on `allocateTransferTransport`, `server.nim:674`); and **(ii)** a **structured rejection signal**, which is itself non-trivial: the reject fires inside `run()`'s accept loop *before* a `reqId` is minted, so none of the four existing `ServerCallbacks` hooks (`onTransferStart/Progress/Complete/Error`) can carry it — A4 must add a new `onRejected` hook + a new `EventKind` + `api.nim` wiring. This is a **sized production sub-slice, not a footnote.** Everything else in Part A is test-only. See §3.1/§4.

## 3. Design

### 3.1 Part A — Facade stateful target (`api.nim` over `Wire`)

**Enabling seam already exists.** `newSession*(…, transportFactory: TransportFactory = nil, listenerFactory: ListenerFactory = nil)` (`api.nim:146-148`) — `TransportFactory = proc(host, port): Transport` (`api.nim:63`). A `TftpSession` can therefore be constructed with a **`Wire`-backed** transport/listener with **zero production refactor**; injection is a test-only concern.

**Baseline shape (holds under every far-side option in Fork A).** A proptest `stateful` `StateMachine` over a real `TftpSession`. Since the transfer/injection/liveness mechanics are the same as v1's `t_hostile`, the **injection-rule builders are extracted into a shared module** — **both** the same-TID family (`mkInject{Data,Ack,Error,Garbage}`, D8a) **and** the off-TID family (`mkInjectOffTid{Data,Ack,Error,Garbage}`, D8b — extra attacker-`(host,port)` param + its own vacuity counter), since Part A's op vocabulary needs off-TID injection too — parameterized over `(wireOf: S -> Wire, notify: (S, bool) -> void)`. **`notify` is read-only in `S`** (typed non-`var`): it inspects `Wire`/Futures (themselves refs) and bumps a counter, so `t_hostile`'s "injection never mutates state beyond the wire + counter" invariant becomes compiler-enforced, not a comment. **`wireOf: S -> Wire` projects the single live Wire per example** — correct for A1b/A2/A3 under Fork A's one-Wire resolution; it deliberately does *not* generalize to A4's N-Wire registry. Imported by *both* `t_hostile.nim` (data phase) and the new facade harness — extract, don't duplicate (~150 lines for both families), don't absorb (`t_hostile` keeps independent value isolating `transfer.nim` without the full session stack).
- **Rules (op vocabulary):** `startTransfer`(get/put), `startServer`, `cancel`, `stop`, a **single shared pump op**, `close`, interleaved with **hostile injection** (forged/garbage/off-TID DATA/ACK/ERROR + malformed RRQ/WRQ + forged OACK, via `wireharness.injectPacket`). The `startTransfer` strategy **varies `mode` (octet/netascii) and blocksize/windowsize extremes** (not a fixed octet default) so the facade's netascii CRLF-straddle state and option paths are exercised under loss/injection.
- **Pump discipline (determinism — architect r1; sized r2):** the invariant hook uses a **fixed-tick pump** (`session.poll(0)` a small fixed N times per step), **never** `drain()`/`waitTransfer()` — both are wall-clock (`epochTime`, `api.nim:658-671`) and would break choice-sequence replay under container jitter. Note `asyncdispatch` is **one process-global dispatcher**: a single `poll(0)` pumps *all* sessions' coroutines, so there is one shared pump op, not per-session polling (which would only look finer-grained, not be). **N must be sized to the longest async hop-chain** — A4's reject chain (client RRQ → `listener.recv` resolves → reject check → `sendError` → `Event` enqueue) needs roughly one dispatcher iteration per `await`; state N and the argument for its sufficiency, and note Wire's callback-ready ordering is **deterministic-by-construction** (software-driven, not OS-multiplexed), so a correctly-sized N is not step-dependent/flaky. Extract this as a **named `pumpSession*(s, ticks = N)` helper** (alongside `wireharness`'s `driveOne`/`driveBoth`) so every Part-A slice inherits one documented tick count instead of re-deriving `t_hostile`'s hard-won magic-3 (R1-1) per file. "`drain`/`close` terminate" is asserted via the **tick cap**, not the wall-clock path.
- **Invariants:** (1) **no `Defect` escapes** api.nim's `except CatchableError` boundaries (`api.nim:411/586/635/668`) under *any* op interleaving + injection; (2) **`poll` never raises** (the yield-outside-try hazard, `api.nim:605`); (3) `drain`/`close` terminate within the tick cap; (4) **`maxConcurrent` enforced** (see A4).
- **Defect-detection is contingent — must be proven, not assumed (architect r1; sharpened r2; corrected r3/impl).** The guarantee that an escaped `Defect` surfaces rests on two facts verified against proptest source: (a) pumping is **synchronous** in the invariant call stack; (b) `src/` contains **zero `asyncCheck`** (a detached Future's Defect would be silently lost). **The message differs by PHASE, not by target shape (implementation finding, A-shared):** a *cold* discovery run (`engine/phases.nim` `randomPhase` ~175-214, the path for any first-time-discovered failure) inlines its own classifier and reports the coarser **`"crashed:"`** (no "strategy" prefix) *regardless* of whether the Defect arose in strategy `generate` or in the property/invariant body; the finer **`"strategy crashed:"`** (`engine/eval.nim` ~92-95, vs plain `"crashed:"` ~110-112) is emitted on the **replay path** (`evalReplay` via `dbReusePhase`). The earlier r2 claim — "for a StateMachine target every invariant-Defect surfaces via `"strategy crashed:"`" — was **too strong**; it holds on replay, not on cold discovery. **The universally-true, always-present guarantee detection actually depends on is the substring `"crashed:"`.** Because A2/A3's real properties run through `fuzzProperty`'s persisted `testId`/`dbPath`, they hit `dbReusePhase` → `"strategy crashed:"` on *every run after the first* — so both messages matter and the canary asserts BOTH paths. So Part A adds: a **Defect-canary** — a committed, **always-run** test (not a bring-up-only manual check; also an explicit acceptance gate on any future proptest pin bump, B4 included), in **two parts**: (i) a direct `evalReplay` of a synthetic Defect raised from inside a `StateMachine` invariant asserting `"strategy crashed:"` (the literal cited replay mechanism), and (ii) a cold `forAll` asserting the universally-true `"crashed:"`. It is distinct in *shape* from `VacuityCounter` (a one-shot assertion, **not** a per-example accumulator) despite the "detection-path analogue" framing. Plus an **`asyncCheck`-in-`src/` tripwire** anchored to the **call form** (`asyncCheck\(`, or comment-excluding) — a bare substring grep would misfire on the lone existing *comment* at `api.nim:581` ("never asyncCheck"), which is prose, not a call.
- **Anti-vacuity (reuse `VacuityCounter`):** hostile packets reached a *live* session; the pump ran mid-hostility; **and** (for A4) an (N+1)th **inbound** request was rejected while the **server's** in-flight count (`server.activeTransfers`) `== maxConcurrent`, observed via A4's structured rejection `Event`. **Note (r2): this is `server.activeTransfers` (the inbound concurrency gate, `server.nim:859`) — NOT `activeClientCount` (`api.nim:127-132`), which counts the session's own *outbound* `startTransfer`s and is a disjoint code path from `maxConcurrent`; asserting against `activeClientCount` would test a condition A4's own construction can never produce.** Liveness for Fork A(b)'s two real sessions checks **both** sides progressed (both futures unfinished / a completed-round-trip counter > 0), not just `not serverFut.finished` (which a client-only early-exit would satisfy vacuously). A vacuous run *fails*.
- **A4 — `maxConcurrent`, made observable (architect r1; sharpened r2).** Two-part: **(prod)** reroute all **three** reject sites (`server.nim:701/852/862`) through `server.transferFactory` (see §2 — plus the new `onRejected`/`EventKind` signal hook, since the reject fires before a `reqId` exists); **(signal)** assert A4 on that **structured signal**, *not* a free-text `evServerLog` substring (uncontracted). A4 needs **N independently-addressable transports** — but **a `Table[port, Wire]` registry keyed on the factory's `port` arg is degenerate under the default config**: with no `portRange` set (`server_config.nim` defaults `portRangeStart/End = 0`, `hasPortRange()` false), `allocateTransferTransport` calls `transferFactory(0)` for *every* transfer (`server.nim:674`) — same key, collapsing the table to one entry. **Fix: reuse the already-proven round-robin call-order index** from `t_session.nim:455-464` (`wireIdx`, which solved this exact degeneracy) to mint a fresh single-peer `Wire` per `transferFactory` call — no port key, no collision mode — *or* explicitly configure an `maxConcurrent+1`-wide port range so `port` becomes a genuine key. A4 may be built with the **hand-fed-`ListenerQueue`** pattern (push N+1 RRQs — proven in `t_session.nim`), **decoupling it from A1a's bridge**.

**Far-side-of-Wire — DECIDED (Corey, architect r1): option (b) — two real sessions, file I/O injected in-memory via the BlockSource/BlockSink seam.** A real client `TftpSession` ↔ real server `TftpSession` over one `Wire`, with the file dependency (`handleRrq`/`handleWrq` reads/writes, `setupGetTransfer`/`setupPutTransfer` `open`) supplied by the **BlockSource/BlockSink in-memory adapter** rather than real disk — so the harness gets full two-sided orchestration coverage (and finally reaches the RRQ/WRQ **negotiation phase** end-to-end, closing v1's R1-7 gap) while staying fast + hermetic + deterministic, avoiding the per-example temp-dir I/O that v1's D8 avoided. **Consequence — Part A's session slices are sequenced *after* the BlockSource/BlockSink RFC** (`in-memory-sources-sinks.md`, drafted, architect round 1). It must land before **A1b onward**. (This is NOT GitHub issue #13 — a separate, already-shipped netascii change; the misattached "#13" label is dropped.) **Unblocked now:** all of Parts B and C (independent), plus **A-shared** and **A1a** (the Wire/listener bridge + injection-module extraction + canary/tripwire have no file dependency).

**Listener seam — genuinely new architecture; the RFC's highest-uncertainty piece (architect r1; specified r2).** `wireharness`'s `ListenerQueue`/`makeListener` exists but is **not connected to `Wire`'s `a2b`/`b2a` queues** — every server-side test (`t_session.nim`, `t_props_server.nim`) hand-feeds the queue (`q.push(rrqBytes,…)`) and `makeTransport`'s `swallowFirst` *discards* the client's first send; none drives a real client's `startTransfer` *into* a listener. Driving a real client→server RRQ over one Wire needs three pieces: **(a)** a per-ephemeral-port `Wire` registry + minting `transportFactory` (mechanical — and **this is A4's transport mechanism too: A4's registry is *this generalized from 1 to N*, not an independent design**, so the two must be built coherently); **(b)** a listener that receives the client's *actual* first send — provisionally `makeListenerFromWire(w: Wire): Transport`, promoting the `swallowFirst`+manual-`push` trick into a first-class object draining the same queue the server's `listenerFactory` listener reads; **(c)** client-side **port adoption** — once the server replies from its freshly-minted per-transfer port, the client `Transport` must learn that port from the incoming packet and redirect subsequent sends (no "which Wire is this response from" concept exists today: one `Wire` = one fixed pair). **Piece (c) is the genuinely novel, highest-risk part.** So A1 splits into **A1a-i** (registry + minting factory, unit-testable alone), **A1a-ii** (listener bridge + client port adoption — the new architecture), and **A1b** (get/put smoke on top). Flag `ListenerQueue` for retirement if unused after. Fork A option (c) skips this bridge entirely.

### 3.2 Part B — Symex extensions (pure cores, opt-in z3 image)

Extend `symexFind` (`sxUnsat` = bounded no-Defect proof; `sxRaised`/`sxSat` = witnesses) to pure, bounded, straight-line targets. **Capability-checked against pinned proptest `99fa2dbe` (architect r1).**
- **`protocol.decode`** — **`seq[byte]` has NO symex witness reader** (`symex.nim` `itSeq` supports only `seq[int]`/`seq[float]`/`seq[ref]`) → calling `symexFind` on `decode(data: seq[byte])` is a **macro-expansion compile error**, the same class v1 hit for `seq[(string,string)]`. Required twin shape: a **`seq[int]` parameter masked to `0..255`** (cast to byte internally) — this *preserves* the variable-length buffer-indexing that is the whole point (naive scalar `val:string` twins would delete it). **Scope:** the fixed-size arms (`opData`/`opAck`/`opError`) get `tIndexError`/`tFieldDefect` bounded proofs directly; the `opRRQ`/`opWRQ` **option-parsing arm loops on input length vs `maxLoopUnwind=5`** (`readOptions`, `protocol.nim:113-123`), so it is a *separate* twin. **Achieved scope (B1 impl finding, corrected from "≤2 options"):** the option arm proves only the **RRQ/WRQ header dispatch + the FIRST cstring (filename) scan** as `sxUnsat` — NOT ≤2 option pairs. A *chained* second bounded scan whose start offset is the first scan's symbolic result returns **`sxUnknown`** (honest "solver could not decide"), invariant under `maxLoopUnwind` (tried 2 and 5), `maxCallDepth` (3 and 20), and `symexAssume` bounding — a genuine dependent-loop solver-capability gap in the pinned proptest, not a modeling choice. (Also surfaced: `symexAssume` parses identically to `symexAssert` — `mkAssert` — rather than the documented early-return filter semantics; **file a proptest ticket** — Corey-owned repo.) So this is an honest bounded proof over the header + first field, not "all RRQs." B1's first slice empirically confirms the `seq[int]`-masked twin compiles — **and (r2) adds a concrete differential oracle**: run the real `decode(seq[byte])` and the masked twin on the *same concrete* byte sequences and assert identical results/exceptions, since "compiles" is a syntax check, not proof the twin takes the same control-flow paths (an incomplete `0..255` constraint could fabricate an `sxSat`/`sxRaised` witness unreachable by any real `seq[byte]`, or diverge in the `shl`/`or` arithmetic). The `0..255` mask must be a z3 constraint on *every* element use, not asserted once at declaration.
- **`security.validatePath` / `checkWriteAccess` (lexical only)** — `string` **is** a supported witness (`itString`→`readString`), so the *signature* is clean — **but the *body* is not (r2): `validatePath` (`security.nim:161-222`) calls `validateWritePath`→`canonicalize`/`symlinkExists`/`hasReparseComponent`, and `checkWriteAccess` calls `canonicalize` — real syscalls absent from proptest's `OpaqueEffectfulProcs` allowlist (`smt/stdlib_models.nim:85-89`), so `symexFind` on the shipped procs will likely hit the same inter-procedural macro-expansion failure B1 works around.** B2 therefore needs its **own test-only twin extraction** (the pre-I/O lexical prefix: `validatePath` lines ~165-204 through `isWithin`; `checkWriteAccess`'s reserved-name check before its `canonicalize` fallback), with B1's same empirical compile-check. The I/O split *is* clean (I/O runs only *after* the lexical checks return `ok`), so the prefix is cleanly extractable. `tRaisedExn`/`tIndexError`.
- **`tftp_uri.parseTftpUri` / `isTftpUri` (r2)** — pure `string`→`string` RFC-3617 parser, same `itString` witness class, no new toolchain. Slices attacker-influenced offsets (`rest[1 ..< closeBracket]`, `hostPort[colonPos+1 .. ^1]`, `params[5 .. ^1]`) → natural `tIndexError`/`tRaisedExn`; reachable from arbitrary embedder strings post-RFC #17, today only 15 hand-written examples (`t_uri.nim`). Fold into the B2 slice.
- **`checksum.writeSidecar`** — the lexical sidecar-path derivation (`string`).
- **`netascii.NetasciiDecoder.feed`/`flush` (r2)** — the wire→local *decode* direction (fed by a hostile/malformed peer; the encoder only sees trusted local bytes). Pure bounded per-call state machine over `openArray[byte]` → hits B1's `seq[byte]`-witness blocker, so B1's `seq[int]`-masked twin transfers directly. Focus the non-conformant-CR branch (`netascii.nim:120-123` — a lone wire `CR` not followed by `LF`/`NUL`), the genuinely hostile arm (module doc cites a prior round-2 false-EOF bug here).
- **tsize unblock** — bump proptest to a build modeling `parseBiggestInt` (confirmed absent in `99fa2dbe`); retire the `parseInt` substitution. **Cross-repo dependency** on the proptest-manifest PR — B1–B3 do **not** depend on it; B4 sequences last. (r2: the dependency is on `github.com/coreyleavitt/proptest` — **Corey's own** sibling repo, not a third-party gate; the `parseBiggestInt` modeling is out-of-band work there, sequenced but not `/tdd`-tracked in *this* RFC — track it with a ticket so B4 doesn't stall for want of one.)

All under the `t_symex*`→z3-image opt-in convention; never in the default suite, never in `src/`.

### 3.3 Part C — Soak campaign + corpus

**Keep the fast default; add a slow campaign that feeds it.** The default stays fixed-seed × `FuzzN`. Separately, a **manually-invoked local campaign** (Environment decided below):
- **`fuzzWith` soak target** — proptest's coverage-guided fuzzer loop (`--panics:off` to catch Defects — confirmed real in `engine.nim:54-59`; the repo sets `--panics:on` nowhere, a **load-bearing premise for A, B, *and* C** — reaffirmed here). **Mode = `fmIR`** (not `fmBytes`): only `fmIR` persists into the same `directoryBasedDatabase`/`tests/corpus` the default replays — which *is* Part C's core success criterion. Cost of that choice (architect r1): `fmIR` seeding is not raw bytes; C2/C3 need a **byte→choice-IR encoder** (matching the `lists(integers(0,255))` continuation-boolean protocol; malformed IR seeds are *silently dropped*, so the encoder needs a round-trip test that **runs the encoded seed through the *actual* soak-target strategy and asserts the concrete generated value equals the intended boundary** — a structural IR round-trip alone is insufficient, since strategies filter/rescale the choice stream and a well-formed IR seed can decode to a semantically inert value). `fmBytes` (trivial raw-byte seeding) is rejected: its corpus lands in a separate on-disk format that never reaches `directoryBasedDatabase` without a hand-built bridge, defeating the replay-by-default goal.
- **Failure behavior (r2)** — on the first Defect/crash a `-Soak` run **stops**, minimizes the triggering choice-sequence, copies it into the committed corpus tagged `origin: soak-crash`, and **exits non-zero** — so an unattended local operator has a defined expectation of what a crash looks like and what lands in the tree.
- **Seed dictionary (C2)** — boundary values (blksize/tsize/windowsize at 2¹⁶/2³²/2⁶³ ±1, zero, negative-ish), known-bad option strings, reserved device names — encoded via the C2 byte→IR encoder.
- **Interop-captured seeds (C3) — capture mechanism must be built first (architect r1).** There is **no pcap/tcpdump capture** anywhere in the repo's interop harness (`docker-compose.yml` runs functional file-content assertions only). C3 therefore has a prerequisite sub-step: add a capture point (a `tcpdump` sidecar on the interop network, or a chapulin debug hook logging raw decoded bytes) before any packet can be harvested. *(Note: the atftp-PUT interop leg has a known always-PASS bug — `echo "PASS…$$?"` reports `echo`'s exit code — so seeds from it carry shape, not a correctness guarantee.)*
- **Corpus minimization (C4)** — proptest ships a real deterministic greedy set-cover over per-entry `Coverage` (`fuzz.nim:337-359`). **Correction (C4 impl):** `minimalCovering()` itself is **private** (no `*` export) → not directly callable from chapulin test code; the only exported door is `FuzzSettings.minimizeCorpus`, consumed at the tail of `fuzz()`/`fuzzWith()`. AND that door only computes real `Coverage` for entries *discovered during that same run* (preloaded `initialIRCorpus` seeds get a zero `Coverage` from `captureIR`, so it can't select them) — so it's "reduce this campaign's fresh discoveries," not "losslessly reduce an external corpus file." C4's resolution: drive the exported door as a **continuation-minimization** (seed from the grown corpus, deterministic `maxIterations` never `timeBudget`) + independently re-verify coverage via exported `inProcessTarget`/`Observation.coverage`. Still de-risked (real minimization, not hand-rolled set-cover: measured 16→9 entries, coverage held 13/13), just via the front door. (Both privacy findings → proptest ticket, Corey-owned repo.) C4 **also** sets a **per-target corpus size ceiling / replay-time budget** so growing the committed corpus doesn't silently slow the fast default (replay scales with corpus size).
- **Coverage-gap reporting (C5) — re-scoped (architect r1).** proptest exposes edge *counts* (`snapshotCoverage`/`Coverage.counters`) but **no reverse map from bitmap slot → source location** (edge IDs are anonymous `(file,line,col)` hashes folded mod 8192). A human-actionable "unvisited edge → file:line" report needs a **new compile-time id→location side table** (a `{.cover.}`-equivalent macro variant) — a full slice of tooling. **C5 is therefore scoped, for now, to the lightweight signal**: report **visited-edge count before/after a campaign** (did the soak expand coverage?), which needs only the existing counters. The full source-mapped edge report is deferred to §8 (considered/deferred). **(r2) C5's own RED-GREEN acceptance test uses a *synthetic* target with deliberately under-covered branches** — asserting `after > before` against a real `src/` target is non-repeatable (v1 already fuzzed these; a converged corpus legitimately yields zero new edges on the coarse 8192-slot bitmap). "Visited-edge count increased on a real target" is a one-time §7 demonstration, not a repeatable automated assertion.
- **Provenance (C4/C6)** — tag committed corpus entries with campaign source/date (an `osTaggedId`-style convention extended to soak-provenance) so a later-failing entry can be triaged (fixed-seed-default vs soak vs interop-capture origin).

**Environment — DECIDED (Corey): local-opt-in only for now.** A manually-invoked local campaign, *not* wired into any CI; the *product* (grown/minimized corpus) is committed and replayed cheaply by the fast default. Automating it (Linux CI / cloud runner) is a future infra RFC; nothing in Part C may assume a CI runner. **Invocation plumbing (architect r1; corrected r2):** the mechanism is **an environment variable, not a compile-time define** — `docker run -e CHAPULIN_SOAK_SECONDS=$N … nim c -r …` + `getEnv("CHAPULIN_SOAK_SECONDS", "0")` read at process start into proptest's **native `FuzzSettings.timeBudget: Duration`** (`fuzz.nim:130-133` — no hand-rolled timer, and crucially **no recompile per budget**; the r1 "`docker run` has no `-e`" note referred to today's *invocation*, not a Docker limitation). To keep `dev-test.ps1`'s existing contract intact ("compile+run named suites, exit failure list") rather than overloading one script/flag namespace with three different meanings of "done," **factor the shared milpa-fetch/mount/image scaffolding into a sourced helper (`scripts/lib/nimcontainer.ps1`, one `Invoke-NimContainer`)** that `dev-test.ps1`, the `-Soak` mode, and the `-CorpusReport` verb all call — capturing the no-duplication goal without merging the contracts (slice C0).

**Ceiling note.** proptest coverage is a coarse pure-Nim 8192-edge bitmap (AST-rewrite, not sanitizer-cov); a big campaign can saturate it. Known limit, not a blocker at chapulin's parser size.

## 4. Cross-cutting

- Reuse v1 infrastructure: `fuzzsupport` (`fuzzProperty`, `VacuityCounter`, `CorpusDir`, generators — reusable **verbatim** at the facade layer, confirmed), the `Wire` harness, the `t_symex*` image convention, `Dockerfile.symex`.
- **Extract the shared injection-rule vocabulary** (§3.1) into one module used by both `t_hostile` and the facade harness — no duplication, no absorption.
- `src/` stays FFI-free and release-no-op.
